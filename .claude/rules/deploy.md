# デプロイ運用

## デプロイ先（`requirements.md` 1.3節・8節が正）

- フロントエンド：Next.js → 無料Vercel
- バックエンドAPI・管理画面：Rails（APIモード）→ 無料Railway（不可時のみRender）
- 認証：Googleログイン（OAuth 2.0 / OpenID Connect）

## ドメイン

- 原則としてドメインは **`rictaworks.jp` のサブドメイン**を使用する（例：`sensorpack.rictaworks.jp`）。

## Webデプロイのセキュリティ

- Webのデプロイは**ヘッドレス**（CLI/API経由の非対話的な実行）で行う。手動のダッシュボード操作に依存しない。
- **バックエンドのドメインは隠蔽する。** RailwayやRenderが払い出す生のバックエンドURLをフロントエンドやユーザーに直接露出しない（フロントエンド経由のAPIプロキシ、またはカスタムサブドメイン経由でアクセスさせる）。

## 作業スコープの境界（重要）

このリポジトリ（Claude Code CLIセッション）での作業は、プラットフォームごとに次の手前までとする。**それ以降はClaude Desktop側で作業する。**

| プラットフォーム | このセッションの担当範囲 | Claude Desktop側の担当 |
|---|---|---|
| Web | 実装・テストまで | **デプロイ以降** |
| デスクトップ・スマホアプリ | 実装・テストまで | **ビルド以降** |
| ESP32 | ファームウェア実装・テストまで | **焼き込み以降** |

CI（自動テスト・lint）はこのリポジトリのスコープ内（`.claude/rules/ci-cd.md`）。実際のCD（本番デプロイ・ビルド・焼き込み）はここでは行わない。
