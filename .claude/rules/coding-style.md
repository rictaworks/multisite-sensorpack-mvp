# コーディングスタイル

`.claude/development-principles.md`（YAGNI/KISS/DRY/SOLID）と合わせて適用する。

## 例外処理・堅牢性

- **フォールバック処理を書かない。** 想定外の状態は握りつぶさず、例外として明示的に処理する。エラーを隠す簡易復旧・デフォルト値による誤魔化しは禁止。
- **例外処理は省略せず丁寧に書く。** 失敗時に何が起きたか分かる形で扱う（Fail Fast）。
- **デバッグトレースができるようにコードを書く。** 処理の要所でログ出力し、後から追跡できる構造にする。

## コード構造

- **制御構文・条件構文（if/for/while等の分岐・繰り返しの骨格）以外のロジックは、必ず関数またはクラスの中に書く。** トップレベルに直接処理を書かない。
- **グローバル変数を禁止する。** 状態は関数・クラスのスコープ内に閉じ込める（セキュリティ・保守性の観点）。

## 文字列・UI表示

- **文字列（UI表示文言・メッセージ等）はハードコードせず、ファイル（i18n用ロケールファイル等）またはDBに分離する。** 詳細は `.claude/rules/i18n.md`。
- **ハードコードされた文字列を検出するテストを書く。**（例：`src/` 配下のソースをスキャンし、i18n関数を経由しない日本語・英語のリテラル文字列がないか検査するテストをCIに組み込む）
- **ネイティブの `alert()` / `confirm()` / `prompt()` はプロジェクト全体で使用禁止。** 確認ダイアログ・入力ダイアログは必ずアプリ内のカスタムUIコンポーネント（モーダル・トースト等）で実装する。`app-ui/` のモックにあるスタイルに合わせる。
- アイコンは **Font Awesome** のみを使用する。絵文字は一切使用しない（コード・UI・コミットメッセージ・ドキュメント全て）。
