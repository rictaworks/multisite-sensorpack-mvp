# テスト運用ルール（TDD厳守）

## 開発フロー

実装は必ず次の順序で進める。順序を飛ばさない。

1. **plan** — 何を作るか、受け入れ条件を先に言語化する
2. **red test** — 先に失敗するテストを書く（実装より先にテストが存在すること）
3. **coding** — テストを通す最小限の実装を書く
4. **green test** — テストが通ることを確認する。通らない場合は3に戻る

## フレームワーク

- Ruby on Rails（APIモード）: **RSpec**
- Next.js（TypeScript）: **Jest**
- フロントエンドの動作確認は次の3手段で行う（`.claude/TM.md` も参照）
  - `curl` — APIレスポンス・ヘッダ・ステータスコードの確認
  - `wget --mirror` — ページの静的取得・リンク切れ確認
  - **Playwright** — 実ブラウザでのE2E（ログイン・画面遷移などの主要導線）

## コミット前セキュリティレビュー（必須）

コミットする前に、以下を必ず参照してセキュリティレビューを行う。

- `.claude/QC10.md`（品質管理10項目）
- `.claude/TM.md`（テストメソッド・フレームワーク概要）
- `.claude/OWASP10.md`（QA観点：OWASP Top 10）
- `.claude/CC.md`（コンプライアンスチェック10項目）

レビューを経ずにコミットしない。`git status` でステージング内容を必ず確認する（シークレットファイルの混入確認を含む）。

## 環境変数

テストに必要な値は `.env` を参照する。値をテストコードにハードコードしない。
