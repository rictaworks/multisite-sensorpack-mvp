# Git / PRワークフロー

## ブランチ運用

- **`main` ブランチでの直接作業は禁止。** 作業は必ずフィーチャーブランチで行う。
- `src/*` 配下に変更が含まれる場合は、**必ずプルリクエストを作成**する（`main` への直接pushは行わない）。
- `src/*` を含まない変更（ドキュメント・設定ファイル・`TASKS/`・`WORK/` 等）は `main` への直接pushを許可する。
- 上記のパス別ルールはGitHub Branch Protectionのpush権限では機械的に強制できない（パス単位のpush制御には非対応のため）。したがってClaude自身の行動ルールとして厳守すること。

## PR本文の必須項目

PRには通常の変更点・テスト内容に加えて、**非エンジニア（クライアント・PM等）でも実施できる、丁寧なユーザーテスト手順**を必ず記載する。

- 専門用語を避け、画面操作を番号付きの手順で書く（例：「1. ○○画面を開く → 2. △△ボタンを押す → 3. □□と表示されることを確認する」）
- 期待される結果（成功時に何が見えるか）を明記する
- 事前準備（テストアカウント・環境URL等）があれば記載する

雛形は `.github/PULL_REQUEST_TEMPLATE.md` を使用する。
