# 環境判定・ログイン運用

## 環境判定（必須）

- アプリケーションは実行環境（development / test / production）を必ず判定し、コード内で分岐できるようにする。
- 環境判定は環境変数（例：`RAILS_ENV`, `NODE_ENV`, `APP_ENV`）を単一の情報源とし、複数箇所で独自に推測しない。

## 開発環境の自動認証（テスト容易性のため許可）

- テスト・開発を容易にするため、**開発環境に限り**「認証済み」の状態に自動分岐してよい（ログイン操作なしでテストできる）。
- ただし以下を厳守する。
  - 環境判定が `production` の場合、この分岐は**絶対に到達不可能**でなければならない（fail closed：判定できない・不明な場合は本番として扱い、自動認証を無効にする）。
  - 本番のUIに、この開発用近道（スキップログインボタン等）を**一切表示・露出しない**。
  - この分岐が無効化されていることを確認するテストを書く（例：`APP_ENV=production` 時に自動認証されないことを検証する）。
  - コミット前レビュー（`.claude/rules/testing.md`）で `.claude/OWASP10.md` のA05（セキュリティ設定ミス）・A07（認証・認可の欠陥）の観点から必ず確認する。

## 本番ログイン

- 一般消費者が実際に使える手段（**Googleログイン**）のみでログインできること。開発者向けの近道を本番UIに露出しない。
- 開発者向け管理画面（`requirements.md` F9）のBASIC認証は、一般消費者向けダッシュボードのログイン導線とは別物であり、混同しない。
