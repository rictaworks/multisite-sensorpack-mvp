# ディレクトリ運用ルール

各ディレクトリの用途に沿って作成・更新すること。

| ディレクトリ | 用途 |
|---|---|
| `TASKS/` | タスク管理（実装単位のタスク・起票内容） |
| `DEBUG/` | バグ報告 |
| `CLIENT/` | クライアント要望・フィードバック |
| `WORK/` | 作業報告 |
| `ENV/DEVELOPMENT.md` | 開発環境の情報 |
| `ENV/PRODUCTION.md` | 本番環境の情報 |
| `SPEC/` | 仕様書、リバースエンジニアリング図解（ER図・DFD・シーケンス図・クラス図・状態遷移図・ユースケース図）。図はMermaid記法で書く |
| `DELETE/` | 削除の代わりに使う手動ゴミ箱（Claudeは削除コマンドを生成しないため、削除したいファイルはここへ移動する） |
| `app-ui/` | デザイン参照専用のモック（`.claude/Manager.md` に準拠し、実装の編集スコープには含めない） |

- `SPEC/` を新設・更新する際、既存の `requirements.md`（ER図・DFD・シーケンス図・クラス図・状態遷移図・ユースケース図を含む現行の生きた仕様書）は引き続き正とする。`SPEC/` は今後の追加・詳細化された仕様やリバースエンジニアリング資料の置き場として使う。
- 図解にはMermaidを使用する。サブプロジェクト（Node/Python等）が作成され次第、Mermaid CLI（`@mermaid-js/mermaid-cli` 等）の導入を検討する。
